## 1장. 우리가 하려는 것이 뭔가

### 퀀트 모델이란?

주식 투자를 "느낌"이나 "뉴스"로 하는 게 아니라, **수치(숫자) 데이터를 기반으로 규칙을 만들어** 자동으로 종목을 고르는 방식이다.

핵심 질문은 딱 하나다:

> **"어떤 주식이 앞으로 42 거래일(약 2달) 동안 시장 평균보다 더 오를까?"**

이 질문에 답하기 위해 우리는:
1. 과거 데이터에서 **패턴**을 찾는다 (머신러닝)
2. 그 패턴이 미래에도 작동하는지 **검증**한다 (백테스트)
3. 검증된 모델로 **실제 종목**을 고른다 (get_picks.py)

## 2장. 모델 파이프라인 — 데이터가 어떻게 흐르는가

```
[원본 데이터 DB]
      ↓
[피처 엔지니어링]   ← "특징 뽑기"
      ↓
[LightGBM 모델]     ← "패턴 학습"
      ↓
[백테스트]          ← "과거로 검증"
      ↓
[포트폴리오 시뮬레이션] ← "실제 수익률 계산"
```

### 2.1 원본 데이터

DB에는 다음 데이터가 들어있다:

| 데이터 종류 | 내용 | 예시 |
|---|---|---|
| 주가 | 매일의 시가/고가/저가/종가/거래량 | 삼성전자 2024-03-15 종가 78,000원 |
| 재무제표 | 분기/연간 손익계산서, 재무상태표 | 영업이익, 자기자본, 현금흐름 |
| 지수 | KOSPI200, 섹터 지수 | KOSPI200 지수 일별 수익률 |
| 구성종목 | 각 지수의 편입 종목 목록 | KOSPI200에 어떤 종목이 있는지 |

### 2.2 피처(Feature)란?

피처는 **모델에 입력하는 숫자 변수들**이다. 우리는 현재 34개를 사용한다.

예를 들어:
- `mom_21d` = 21일 수익률 (최근 한 달에 얼마나 올랐나)
- `roe` = 자기자본이익률 (기업이 자본을 얼마나 효율적으로 쓰나)
- `earnings_growth_yoy` = 전년 동기 대비 순이익 증가율

모델은 이 37개 숫자를 보고 **"이 종목이 다음 42일에 잘 갈 것 같다/아닌 것 같다"** 를 판단한다.

#### 피처 카테고리 (우리가 사용하는 34개)

| 카테고리 | 개수 | 대표 피처 | 측정하는 것 |
|---|---|---|---|
| 모멘텀(학술형) | 4 | `ma_ratio_20_120` | 단기 MA / 장기 MA |
| 거래량/유동성 | 2 | `amihud_21d` | 유동성 부족 위험 |
| 변동성/리스크 | 1 | `rolling_beta_60d` | 시장 대비 민감도 |
| 펀더멘털 | 5 | `roe`, `earnings_growth_yoy` | 기업 수익성/성장 |
| 시장 맥락 | 1 | `market_regime_120d` | 전체 시장 상황 |
| 섹터 | 4 | `sector_momentum_21d` | 업종 흐름 |
| 섹터 중립화 | 9 | `sector_zscore_mom_21d` | 업종 내 상대 위치 |
| 부실 감지 | 3 | `distress_composite_score` | 위험 종목 걸러내기 |
| 섹터 로테이션 | 3 | `sector_rotation_signal` | 업종 교체 신호 |
| 매크로 상호작용 | 2 | `conditional_momentum` | 시장 환경 × 모멘텀 |

### 2.3 타깃(Target)이란?

타깃은 **"모델이 맞춰야 하는 정답"** 이다.

우리는 `target_residual_rank_42d`를 사용한다.

이것을 분해하면:
- `42d` → 42 거래일 뒤의 수익률
- `residual` → 시장 수익률과 베타를 제거한 **순수 알파** 부분
- `rank` → 절대적인 수익률이 아니라 **전체 종목 중 몇 위인가**로 표현

**왜 rank를 쓰냐?** 수익률은 -20%~+200%처럼 분포가 극단적이라 학습이 어렵다. 1위~500위처럼 순위로 변환하면 분포가 균일해져서 모델이 더 잘 학습한다.

**왜 residual을 쓰냐?** 삼성전자가 올랐다고 해서 그 모델의 공인가? 그냥 KOSPI가 오른 것일 수도 있다. 시장 전체 움직임(베타×시장수익률)을 제거하면, **모델이 진짜로 종목 선택 능력이 있는지** 알 수 있다.

## 3장. 워크 포워드 백테스트 — 어떻게 검증하나

### 3.1 왜 과거 데이터로만 검증하면 안 되나?

가장 흔한 실수: "과거 2010~2026년 전체 데이터로 학습하고, 같은 기간으로 수익률 계산"

이건 **시험지를 미리 보고 시험 보는 것**과 같다. 당연히 결과가 좋게 나온다. 이를 **룩어헤드 바이어스(Look-ahead bias)** 라고 한다.

### 3.2 워크 포워드(Walk-Forward)란?

```
Fold 1:  [2015 2016 2017] 학습   43일 공백   [2018] 테스트
Fold 2:  [2016 2017 2018] 학습   43일 공백   [2019] 테스트
Fold 3:  [2017 2018 2019] 학습   43일 공백   [2020] 테스트
...
Fold 9:  [2023 2024 2025] 학습   43일 공백   [2026] 테스트
```

핵심 규칙:
- **테스트 기간의 데이터는 절대 학습에 사용 안 한다**
- **43일 공백(embargo)**: 학습 마지막 날과 테스트 시작일 사이에 43일을 비워두는 이유는, 42일 타깃이 테스트 데이터와 겹치는 것을 막기 위해서

### 3.3 조기 종료(Early Stopping)란?

LightGBM은 트리를 하나씩 추가하면서 학습한다.
- 트리를 너무 적게 쓰면 → **과소적합(underfitting)**: 패턴을 못 찾음
- 트리를 너무 많이 쓰면 → **과적합(overfitting)**: 학습 데이터에만 맞고 실전에서 안 통함

해결책: **검증 세트(Validation Set)** 를 따로 떼어놓고, 거기서 성능이 더 이상 안 좋아지면 학습을 멈춘다.

우리의 경우:
- 학습 3년 중 **마지막 1년**을 검증 세트로 사용
- **Huber Loss** 기준으로 조기 종료 (안정적인 기준)
- **IC(Information Coefficient)** 는 별도로 로깅만 함 (모니터링용)

## 4장. 백테스트 결과 해석법

이제 실제 출력 결과를 보면서 각 숫자가 무엇을 의미하는지 배우자.

### 4.1 학습 로그 읽기

```
[Fold 2021] start (train=2018-2020, train_rows=273,927, test_rows=129,173)
Training until validation scores don't improve for 300 rounds
[100]    valid_0's huber: 0.0416988    valid_0's ic: 0.00454472
...
Early stopping, best iteration is:
[24]    valid_0's huber: 0.04166    valid_0's ic: 0.0159159
[Fold 2021] IC  train=0.1736  val=0.0913  ratio=0.53  OK
```

| 항목 | 의미 |
|---|---|
| `train=2018-2020` | 이 폴드의 학습 데이터 기간 |
| `best iteration: 24` | 24번째 트리에서 조기 종료됨 |
| `huber: 0.0416` | Huber 손실값 (낮을수록 좋음) |
| `ic: 0.0159` | IC (높을수록 좋음, 보통 0.05~0.15가 현실적) |
| `train=0.1736` | 학습 데이터에서의 IC |
| `val=0.0913` | 검증 데이터에서의 IC |
| `ratio=0.53` | val_IC / train_IC = 0.53 → 절반 이상 유지 → **OK** |

#### IC(Information Coefficient)란?

IC = 모델의 예측 순위와 실제 수익률 순위 간의 **스피어만 상관계수**

- IC = 1.0 → 예측 순위와 실제 수익률 순위가 완벽하게 일치
- IC = 0.0 → 아무 상관 없음 (동전 던지기 수준)
- IC = -1.0 → 완벽하게 반대

실제 퀀트 모델에서 IC 0.05~0.10이면 꽤 좋은 모델이다. IC 0.15+ 이면 매우 훌륭하다.

#### 과적합 판단 기준

| IC ratio | 판단 |
|---|---|
| ≥ 0.5 | OK — 검증에서 절반 이상 유지 |
| 0.3 ~ 0.5 | 경계선 |
| < 0.3 | ⚠ OVERFIT — 학습 데이터에 과도하게 맞춰짐 |

```
[Fold 2018] IC  train=0.2349  val=0.0459  ratio=0.20  ⚠ OVERFIT
```
이 폴드는 학습 IC의 20%만 검증에서 유지됨 → 과적합 신호.  
**하지만 이 폴드의 OOS(실제 테스트) 성과는 -6.11% → 시장 대비 +12.60%**  
즉, IC ratio 낮다고 반드시 실전 성과가 나쁜 건 아니다.

#### best_iter가 너무 작으면?

```
[Fold 2019] best iteration: [15]
```

트리 15개로 학습이 끝났다는 것 → **퇴화 모델(Degenerate model)**

정상적인 모델은 수백~수천 개의 트리가 필요하다. 15개로 끝났다는 건:
- 검증 세트와 테스트 기간의 **시장 환경이 완전히 달라서** (제도 불일치, Regime Mismatch)
- 검증 세트에서 Huber loss가 처음부터 최솟값이라 개선이 없음

**2019 폴드의 경우:** 검증 세트 = 2018년 하반기(하락장), 테스트 = 2019년(상승장)  
모델이 하락장 패턴에 맞게 조기 종료됐지만, 실제 OOS는 +7.58%로 괜찮았다.

#### 수익률 관련

>
> - `universe_cap` (시총가중, 권장): 232% → 알파 78% — 사이즈 프리미엄 제거, 순수 stock selection
> - `kospi200` (기본값): ~211% → 알파 ~99% — 사이즈/KOSDAQ 프리미엄 포함
> - `universe` (동일가중): ~289% → 소형주 과대 대표

#### 리스크 지표

| 지표 | 값 | 해석 |
|---|---|---|
| Ann. Vol | 17.60% | 연간 변동성 (낮을수록 안정적) |
| Max Drawdown | -20.66% | 고점 대비 최대 낙폭 |
| Max Underwater | 10 rebals | 손실 구간이 최대 10번의 리밸런싱(약 1.7년) 지속 |

#### 종합 성과 지표 (핵심!)

**샤프 비율(Sharpe Ratio)**

```
Sharpe = (연평균 수익률 - 무위험 수익률) / 연간 변동성
```

쉽게 말하면: **"리스크 1단위당 얼마나 벌었나?"**

| Sharpe | 판단 |
|---|---|
| < 0.5 | 나쁨 |
| 0.5 ~ 1.0 | 보통 |
| 1.0 ~ 1.5 | 좋음 |
| 1.5+ | 매우 좋음 |

현재 우리: **0.96** → 보통~좋음 경계

**칼마 비율(Calmar Ratio)**

```
Calmar = 연평균 수익률 / |최대 낙폭|
```

얼마나 적게 잃으면서 얼마나 버냐의 비율.

현재 우리: **0.91** → 좋음 (낙폭이 20.7%인데 연 18.8% 수익)

### 4.3 시장 체제 분석 (Market Regime Analysis)

```
Up Capture:    0.92   (시장이 1% 오를 때 포트폴리오는 0.92% 오름)
Down Capture:  0.22   (시장이 1% 내릴 때 포트폴리오는 0.22% 내림)
Overall Beta:  0.44   (시장 민감도)
```

**다운 캡처(Down Capture) 0.25** 가 핵심이다.

시장이 -10% 빠질 때 우리 포트는 -2.5%만 빠진다는 뜻이다.  
이것이 **하방 방어력**이고, 이 모델의 가장 강한 특성이다.

왜 중요하냐?
- 상승장에서 92% 따라가고
- 하락장에서는 22%만 따라간다면
- 장기적으로 엄청난 복리 이점이 생긴다

### 4.4 통계적 유의성 검정

```
OLS t-stat      t=+2.96  p=0.005  ***
NW HAC t-stat   t=+2.56  p=0.013  **
Sharpe t-stat   t=+2.96  p=0.005  ***
IC t-stat       t=+5.47  p=0.000  ***
Binomial (hit)           p=0.161  (fail)
Bootstrap Sharpe CI  95% CI [0.39, 1.71]
4/5 tests pass at 5%; 3/5 pass at 1%
```

"이 수익률이 운이 아니라 진짜 실력인가?" 를 확인하는 것.

| 검정 | 의미 |
|---|---|
| OLS t-stat | 초과 수익이 통계적으로 0이 아닌가 |
| NW HAC t-stat | 시계열 자기상관을 보정한 버전 (더 보수적) |
| Sharpe t-stat | 샤프 비율이 운으로 나올 확률 |
| IC t-stat | IC가 우연히 나올 확률 |
| Binomial | 히트율이 동전 던지기보다 나은가 (50번 리밸런싱은 검정력 부족) |

**p < 0.05** 면 "5% 수준에서 통계적으로 유의하다" → 운이 아닐 가능성이 95%

현재: 4/5 통과 → **강한 통계적 근거** (Binomial은 50개 샘플 부족으로 검정력 낮음)

### 4.5 퀀타일 수익률 — 모델의 순위 능력

```
Q1(Worst)  Q2      Q3      Q4      Q5(Best)
+2.68%   +3.16%  +2.60%  +3.21%  +3.38%   [NOT MONOTONIC]
```

모든 종목을 모델 점수 기준으로 5등분:
- Q1 = 모델이 "나쁘다"고 한 하위 20%
- Q5 = 모델이 "좋다"고 한 상위 20%

**이상적인 패턴:** Q1 < Q2 < Q3 < Q4 < Q5 (단조 증가)

**우리의 문제:** Q3(3.72%) > Q4(3.17%) → **단조성 위반**

무엇을 의미하냐?
- 극단 선별은 잘 한다 (Q1이 가장 낮음, Q5가 높음)
- **중간 구간 변별력이 부족하다**
- Q4와 Q5를 제대로 구분 못 한다

이것이 개선 과제 중 하나다.

### 4.6 Long-Short 성과

```
Long-Short (Top 10% - Bottom 10%): 7.18%  Sharpe 0.38
```

모델 점수 상위 10% 매수, 하위 10% 공매도 했을 때의 연간 수익률과 샤프.

이것은 **순수한 모델의 랭킹 능력**을 측정한다.  
포트폴리오 구성, 섹터 중립화 등 모든 구현 디테일을 빼고 본 순수 신호 강도.

롱숏 샤프 0.38 → 신호는 존재하지만 약함. 개선 여지 있음 (목표: 1.0+).

## 5장. 우리가 시도한 것들 — 실험 기록

이 섹션은 "왜 그걸 했고, 어떻게 됐는지"를 솔직하게 기록한다.

### 5.1 문제 1: 퇴화 모델 (best_iter = 15, 23)

**증상:**
- Fold 2019에서 best_iter = 15 (정상: 수백~수천)
- Fold 2021에서 best_iter = 23

**처음 의심:** "모델 용량이 너무 작아서 학습이 빨리 끝나는 거 아닐까?"

```python
# 기존 (너무 제한적)
num_leaves=7, max_depth=3, min_data_in_leaf=1500

# 시도한 것 → 더 복잡한 모델
num_leaves=31, max_depth=6, min_data_in_leaf=500
```

**결과:** 실패. 학습 IC는 올라갔지만 OOS 성과가 나빠졌다.
- Sharpe: 1.30 → 1.15
- 과적합이 심해짐

**진짜 원인:** 모델 용량 문제가 아니라 **검증 세트 시장 체제 불일치**
- Fold 2019: 검증 = 2018년 하반기(하락장), 테스트 = 2019년(상승장)
- 하락장에서 최적화된 모델이 상승장에서 작동 안 함
- 하지만 **실제 OOS 성과는 +7.58%로 괜찮았다** → 퇴화 모델이 문제가 아님

**교훈:** 학습 지표(best_iter, IC ratio)가 나쁘다고 반드시 OOS가 나쁜 게 아니다.

---

### 5.2 문제 2: 퀀타일 단조성 위반

**증상:** Q3 > Q4 → 모델이 Q4와 Q5를 잘 구분 못 함

**원인 진단:**
- SHAP 분석으로 피처 기여도 확인
- 상위 5개 피처가 전체 중요도의 43.2% → 농도 문제 (acceptable)
- ROE + sector_zscore_ROE, GPA + sector_zscore_GPA → **중복 신호 26.4%**
- 모멘텀 변형 13개 → **21.9% 기여, 중복이 많음**
- `sector_zscore_volume_ratio_21d` → **기여도 0.0% (죽은 피처)**

### 5.3 시도 1: 수익의 질(Accruals) 피처 추가

**아이디어:**
- `accrual_ratio` = (순이익 - 영업현금흐름) / 총자산
  - 양수 = 이익이 현금보다 많음 → **수익 품질 낮음**
  - 음수 = 현금이 이익보다 많음 → **수익 품질 높음**
- `cfo_to_ni` = 영업현금흐름 / |순이익|
  - 1 이상 = 현금이 이익을 초과 → **좋은 신호**

**실패 1 (fillna=0.0):**
- 결측값을 0.0으로 채웠더니 "순이익 없음 또는 마이너스 순이익"과 "발생액이 0인 정상 기업"을 구분할 수 없었다
- 첫 번째 트리가 이 이분법적 특성에 과적합 → best_iter = 1
- Sharpe: 1.30 → 1.08

**실패 2 (섹터-날짜 중앙값으로 결측 보정):**
- 결측값 보정 방식은 개선됐지만 근본 문제가 남아있었다
- **코로나 회복장(2020)에서 현금이 부족한 기업들이 오히려 많이 올랐다**
- 사이클 업종, 재무가 나쁜 기업들이 회복 바운스를 주도
- 수익의 질 신호가 이 시기에는 역방향 → Fold 2021 best_iter = 1
- Sharpe: 1.30 → 1.04

**교훈:** 수익의 질 신호는 **시장 체제에 따라 방향이 바뀐다(regime-conditional)**. 단순 회귀 모델에서는 쓰기 어렵다.

---

### 5.4 성공: 분기별 YoY 순이익 성장률

**아이디어:**
```
earnings_growth_yoy = (올해 Q순이익 - 작년 같은 Q순이익) / |작년 Q순이익|
```

DART 공시 데이터는 **YTD(연초 누계)** 형식이라, 분기 순이익을 역산해야 한다:
- Q1 분기 순이익 = Q1 YTD
- Q2 분기 순이익 = 반기 YTD − Q1 YTD
- Q3 분기 순이익 = 3Q YTD − 반기 YTD
- Q4 분기 순이익 = 연간 YTD − 3Q YTD

**왜 accruals와 달리 성공했나?**
- 코로나 회복(2021)에서 실적이 좋아진 기업이 많았다 → 신호 방향이 유지됨
- 단순히 "실적이 좋아지고 있나?" 를 묻는 신호 → 체제 의존성이 낮음

**결과:**
| 지표 | 이전 | 이후 |
|---|---|---|
| Sharpe | 1.30 | **1.34** |
| Calmar | 1.50 | **1.54** |
| Hit Rate | 56% | **66%** |
| Long-Short Sharpe | 0.67 | **0.77** |
| 2021년 수익률 | +7.64% | **+47.33%** |
| 통계 검정 통과 | 4/5 | **5/5** |

2021년이 +7.64%에서 +47.33%로 점프한 이유:
- 2020년 기저 효과로 2021년에 발표되는 YoY 순이익 성장률이 폭발적
- 모델이 이 성장 가속 신호를 포착해서 해당 종목을 선별

---

### 5.5 시도했지만 포기한 것: 멀티 제도 검증 세트

**아이디어:** 검증 세트를 마지막 1년이 아니라, 각 연도의 마지막 25%를 사용
→ 다양한 시장 환경을 검증에 포함시키면 더 강건해지지 않을까?

**결과:**
- IC IR: 0.83 → 1.23 (개선!)
- 하지만 Beta: 0.44 → 0.61 (시장 추종이 강해짐)
- Down Capture: 0.22 → 0.45 (하방 방어력 약화!)
- 2022 하락장: -4% → -13%

**원인:** Q4 계절 패턴(4분기에 주가가 오르는 경향)이 다중 제도 검증에서 학습됨. 모델이 "Q4에 오르는 주식"을 선택하게 됨 → 시장 상관성이 올라가고 하방 방어가 깨짐.

**교훈:** 검증 세트 구성도 "알파"에 영향을 줄 수 있다. 더 좋아 보이는 IC가 더 나쁜 포트폴리오를 낳을 수 있다.

---

### 5.6 시도했지만 포기한 것: IC 기준 조기 종료

**배경:** Huber loss 최솟값 ≠ IC 최댓값. 우리는 IC를 신경 쓰는데 왜 Huber loss로 학습을 멈추나?

**시도:** `feval`로 IC를 커스텀 평가 지표로 추가하고, IC 기준으로 조기 종료

**결과:** 완전히 실패
- IC는 첫 1~5개 트리에서 급등(첫 번째 분기에서 강한 횡단면 신호 포착)
- 이후 IC가 급격히 떨어짐
- IC 기준 조기 종료 → best_iter = 1 → 트리 1개짜리 모델

**교훈:** IC는 학습 초반에 노이즈가 너무 많다. Huber loss는 안정적인 수렴 신호를 준다. **현재 해법: Huber로 조기 종료 + IC는 로깅만** (`first_metric_only=True`)

---

### 5.7 시도했지만 포기한 것: 복합 멀티 호라이즌 타깃

**아이디어:** 단일 42일 타깃 대신 여러 기간을 블렌딩하면 라벨 노이즈가 줄고 퀀타일 단조성이 개선되지 않을까?

```python
# 시도한 타깃
target = 0.4 × residual_rank_21d + 0.4 × residual_rank_42d + 0.2 × residual_rank_63d
```

**결과:** 실패

| 지표 | 이전(42d 단독) | 이후(복합) |
|---|---|---|
| Sharpe | 1.34 | **1.12** |
| Total Return | 492% | **246%** |
| Alpha vs KOSPI200 | +281% | **+35%** |
| Hit Rate | 66% | **56%** |
| 퀀타일 단조성 | NOT MONOTONIC | **여전히 NOT MONOTONIC** |

**원인:** 42일 포트폴리오에 21일/63일 신호를 섞으면 중간 분위(Q2~Q4) 노이즈가 증가한다. 퀀타일 문제는 라벨 노이즈가 아니라 **알파 다양성 부족** 때문이므로, 타깃 블렌딩이 근본 원인을 해결하지 못한다.

**교훈:** 라벨 노이즈 감소는 동일 기간 내 앙상블에서만 효과적. 다른 기간을 섞으면 호라이즌 미스매치로 노이즈가 오히려 증가한다.

---

### 5.8 시도한 것: 포트폴리오 가중치 (Signal-Proportional Weighting)

**아이디어:** top-50 동일비중 대신 모델 신호 강도에 비례하게 가중치를 주면 어떨까?

```bash
--weighting signal      # weight ∝ score_rank
--weighting signal_vol  # weight ∝ score_rank / volatility_21d (리스크 조정)
```

**결과 (2010–2026, horizon=42, top-50, 200B+ KRW):**

| 모드 | Total Return | Sharpe | Max DD | Calmar |
|---|---|---|---|---|
| `equal` (기본값, universe_cap) | 310% | **0.96** | **-20.7%** | **0.82** |
| `signal` ¹ | ~552% | 1.30 | -17% | 1.34 |
| `signal_vol` ¹ | 371% | 1.21 | -19.5% | 1.07 |

> ¹ `signal` / `signal_vol` 실험은 오염된 baseline(KOSPI200 벤치마크, 37 피처) 기준.

**결론:**
- `signal`: 총수익은 높지만 Max DD 악화, Calmar 저하. IC=0.06의 약한 신호로 극단 집중 시 리스크 비용이 수익 이득을 초과.
- `signal_vol`: 3가지 중 최하. 저변동성 대형주를 과중해 모델 conviction이 낮은 종목에 자본이 쏠림.
- **기본값 `equal` 유지. 리스크 조정 기준으로 가장 우수.**

## 6장. 현재 남은 문제와 개선 방향

### 6.1 여전히 해결 안 된 것: 퀀타일 단조성

```
Q2(3.16%) > Q3(2.60%) — 모델이 중간 구간을 잘 못 구분
```

Long-Short Sharpe가 0.38인데, 이상적으로는 1.0+이 목표다.

**왜 이게 어려운가?**
- 극단적인 종목(확실히 나쁜 것, 확실히 좋은 것)은 모델이 잘 잡는다
- 중간 종목들은 본질적으로 구분하기 어렵다
- 기존 피처들이 가격/모멘텀에 집중되어 있어 중간 구간의 추가 신호가 부족하다

**가능한 해결 방향:**
1. 애널리스트 컨센서스 데이터 (FY1 EPS 추정치 변화) → DB에 없음, 외부 구매 필요
2. 단기 이익 서프라이즈 (SUE) → 마찬가지로 컨센서스 데이터 필요
3. 죽은 피처(`sector_zscore_volume_ratio_21d`) 제거 → 무료로 슬롯 1개 확보

> ⚠ **복합 멀티 호라이즌 타깃 (`0.4×21d + 0.4×42d + 0.2×63d`) — 5.7에서 이미 시도, 실패.** 퀀타일 개선 없음, Sharpe 1.34→1.12. 재시도 금지.

### 6.2 구조적 한계

**데이터 한계:**
- 분기 데이터가 2016년부터만 있음 → 초기 폴드(2018 테스트)는 2년치 분기 이력만 있음
- 애널리스트 추정치 없음 → 진짜 SUE 계산 불가

**모델 구조 한계:**
- 시장 체제(상승장/하락장/위기장)를 모르는 단일 모델
- 2019 폴드처럼 학습-테스트 간 체제 불일치 시 best_iter가 매우 낮아짐
- 이것이 진짜 성과에는 큰 문제가 없었지만, 잠재적 불안정 요인

## 7장. 모델을 개선하려면 뭘 봐야 하나?

### 새로운 피처를 추가할 때 체크리스트

1. **커버리지 ≥ 70%** — 결측값이 많으면 행이 통째로 날아감
2. **결측값 보정 전략** — `fillna(0.0)` 금지. 섹터-날짜 중앙값 또는 의미 있는 기본값 사용
3. **체제 의존성 확인** — 코로나 폴드(Fold 2021)에서 best_iter > 50 유지되는가?
4. **실제 OOS 확인** — IC ratio가 낮아도 OOS가 괜찮은 경우가 있음
5. **기존 피처와 상관관계** — 이미 있는 신호와 너무 유사하면 추가 가치 없음

### 결과를 볼 때 우선순위

1. **Sharpe + Calmar** — 전체 품질
2. **Down Capture** — 우리 모델의 핵심 강점, 이게 올라가면 경계
3. **Long-Short Sharpe** — 순수 신호 강도
4. **Fold 2021 best_iter** — 새 피처의 체제 의존성 판별기
5. **통계 검정 통과 수** — 운인지 실력인지

### 절대 하지 말아야 할 것

| 유혹 | 이유 |
|---|---|
| 모델 아키텍처 교체 (LightGBM → XGBoost/NN) | 아키텍처가 병목이 아님 |
| 유사한 피처 변형 추가 | 중복 신호, 퀀타일 스프레드 악화 |
| 과거 성과 좋아 보이도록 파라미터 조정 | 커브 피팅 (미래에 안 통함) |
| 검증 없이 여러 개 동시 변경 | 무엇이 효과 있었는지 모름 |
| 복합 멀티 호라이즌 타깃 재시도 | Sharpe 1.34→1.12, 퀀타일 개선 없음. 5.7 참고 |
| `--weighting signal_vol` 재시도 | Sharpe/Calmar 모두 악화. 5.8 참고 |
| `fillna(0.0)` 사용 | Fold 2021 best_iter=1 재발. 반드시 섹터-날짜 중앙값 보정 |

## 부록: 자주 쓰는 용어 사전

| 용어 | 한국어 | 설명 |
|---|---|---|
| Alpha | 알파 | 시장 대비 초과 수익 |
| Beta | 베타 | 시장 움직임에 대한 민감도 |
| IC | 정보 계수 | 예측과 실제의 상관계수 |
| IC IR | IC 정보비율 | IC 평균 / IC 표준편차 (일관성) |
| Sharpe | 샤프 | 리스크 단위당 수익 |
| Calmar | 칼마 | 최대 낙폭 대비 수익 |
| Drawdown | 낙폭 | 고점에서 얼마나 떨어졌나 |
| Walk-Forward | 워크 포워드 | 시간 순서를 지킨 백테스트 |
| Embargo | 엠바고 | 학습-테스트 사이 공백 |
| Regime Mismatch | 체제 불일치 | 학습/검증/테스트의 시장 환경이 다른 것 |
| Overfitting | 과적합 | 학습 데이터에만 맞고 실전에서 안 통함 |
| Quintile | 퀀타일 | 5등분 |
| Long-Short | 롱숏 | 상위 매수 + 하위 공매도 |
| PIT | Point-in-Time | 해당 날짜에 실제로 알 수 있었던 데이터만 사용 |
| YTD | Year-to-Date | 연초 누계 |
| YoY | Year-over-Year | 전년 동기 대비 |
| Huber Loss | 후버 손실 | 이상치에 강건한 손실 함수 |
| DART | 다트 | 금융감독원 전자공시시스템 |
| sector-neutral | 섹터 중립 | 업종 효과 제거 |
